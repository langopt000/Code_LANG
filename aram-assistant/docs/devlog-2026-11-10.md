## LOL 海克斯大乱斗实时助手（aram-assistant/）
- 用户需求：基于 aramkit.cn，做对局内插件，覆盖英雄选择排行、海克斯三选一胜率/评级、结合当前海克斯的出装顺序。
- 关键技术发现：
  - aramkit.cn 是 Nuxt 预渲染 HTML，`dataset=high` 在客户端生效；真实数据源是其公开静态 JSON：`https://data.aramkit.cn`，版本清单 `data/versions.json`。
  - 路径模板：`{dataPath}/stats/{all|high}/...`（champion-rankings.json / augment-rankings.json / champion-details/{id}.json / champion-details/{id}-single-augments.json / augment-details/{id}.json）；中文名称资源：`{resourcePath}/zh-CN/resources/{champions|augments|items|archetypes}.json`。
  - `champion-details/{id}-single-augments.json` 含按单个海克斯拆分的出装 profiles/routes（starters、boots、purchaseOrder、laterItems、slots），是「结合海克斯推荐出装顺序」的核心。
  - Riot 的 LCU / Live Client Data 接口都不暴露海克斯卡牌，商业插件也靠屏幕 OCR；本项目用 Windows 自带 Windows.Media.Ocr + GDI 截屏，零第三方依赖。
  - ARAMKit 官网已有免费开源桌面客户端（/zh-CN/client），覆盖海克斯胜率与出装注入；本项目补足英雄选择阶段排行与显式海克斯联动出装顺序。
- 实现：纯 Python 3 标准库 + 本地 HTTP 服务(127.0.0.1:8765) + 单页 HTML 控制台；Edge/Chrome `--app` + Win32 API 实现置顶透明浮窗。文件：app.py / datafeed.py / league.py / vision.py / engine.py / window.py / ocr.ps1 / ui/index.html / start.bat。
- 验证：真实 v16.22 高分段 4,297,659 场样本；173 英雄 / 239 海克斯 / 197 装备；OCR 中文识别链路在本机跑通；无头浏览器渲染页面正常。
- 限制：需 League 客户端运行；OCR 依赖中文语言包与识别区域校准；第三方软件合规性需用户自行确认所在服务器规则。

## 追加：绑定开机自启 / 客户端唤醒
- 用户要求：检测到 League 客户端打开就自动打开插件。
- 方案：`watcher.py` 常驻守护（单实例锁 127.0.0.1:8766），`tasklist` 每 5s 检测 `LeagueClientUx.exe`；出现则拉起 `app.py`，退出超 120s 则关浮窗并停自己拉起的服务。日志 `data/watcher.log`，`data/watcher.stop` 为优雅停止标志。
- `app.py` 新增 `autoOverlay` / `autoCloseOverlay`：phase 变为 ChampSelect/InProgress/GameStart/Reconnect 时后台线程自动 `launchOverlay`；回到 None 自动收起；用户手动关闭浮窗会带 `fromUser` 标记，本局不再反复弹出。端口占用时不再崩溃，直接打开已有控制台。
- 开机自启：Startup 文件夹放 `ARAM-Mayhem-Assistant.vbs`（隐藏窗口，主）+ `ARAM-Mayhem-Assistant.cmd`（不依赖脚本宿主，备用），两者由单实例锁去重；`setup_autostart.py` / `remove_autostart.py` + 同名 bat 安装与卸载。
- 环境注意：本会话沙箱会回收长驻子进程，且禁止 wscript/cscript/COM 实例化，所以登录时的 VBS 执行无法在会话内验证；但 `cmd /c autostart.cmd` 与 Python 分离进程两条链路均已实测能拉起守护并启动服务。
- 验证：`/api/state` 返回 autoOverlay、setAutoOverlay 开关生效、config.json 默认 true、JS/Python 语法与无头渲染均通过。

## 追加：国服 LCU 连接修复 + 连接自检
- 用户反馈"客户端主页面看不到插件"。诊断发现守护/服务都在跑、客户端进程在，但 `clientConnected=False`，导致 phase 恒为 None、自动浮窗不触发。
- 根因：国服 WeGame 版 `LeagueClientUx.exe` 的 WMI CommandLine / ExecutablePath 读不到（权限受限），`lockfile` 为 0 字节。
- 解决：`league.py` 增加两级 fallback —— 用 `winreg` 读 `HKCU\SOFTWARE\Tencent\LOL InstallPath` 等注册表定位安装目录，优先读 lockfile；为空则扫描 `*LeagueClientUx.log`（客户端日志首行含 `--app-port` 与 `--remoting-auth-token`），并用 `_verify()` 实际请求 `/lol-gameflow/v1/gameflow-phase` 校验候选凭据。记录 `source`（wmi/lockfile/log）。
- 实测：端口 7686、凭据来源 log、phase `InProgress`（用户当时其实在对局里）、Live Client Data 可用，浮窗自动弹出，自检 6 项全绿。
- 新增 `/api/diagnose` 与 UI「连接自检」面板（守护/服务/客户端进程/LCU/LiveData/浮窗 6 项 + 提示），以及 `testOverlay`（强制弹窗）与 `redetect`（强制重连）控制动作。
- 环境限制补充：本会话沙箱会回收由工具调用拉起的后台进程，服务无法由助手长期保持；必须由用户从桌面双击 `setup_autostart.bat` / `start.bat`，或重启登录由启动项拉起。答复中需明确此点。
- 设计说明：大厅/主页面不弹浮窗，仅 ChampSelect/InProgress 才自动弹，这是用户"看不到"的另一半原因。

## 追加：游戏内浮窗形式与显示问题排查
- 用户开了无边框游戏，要求看浮窗在游戏里怎么体现；实测抓屏发现浮窗根本没显示。
- 依次定位并修复（全部在 window.py / app.py / ui/index.html）：
  1. `subprocess.Popen(..., CREATE_NO_WINDOW)` 会把 Chromium 主窗口一起隐藏 → 去掉该 flag。
  2. `_find_hwnd()` 里 `found.append(a, b)` 写成两个参数，ctypes 回调抛异常被静默吞掉，导致永远"找不到句柄"→ 改成 append 单个 tuple，并放宽为按 PID + 可见 + 尺寸≥200 匹配（--app 窗口标题可为空）。
  3. 系统 125% DPI：Chromium `--window-size/position` 用逻辑像素，Win32 SetWindowPos 用物理像素 → 新增 `dpi_scale()`，启动参数除以 scale，`place()` 仍用物理像素。
  4. Edge profile 单例锁导致新进程把 URL 转给旧实例后退出 → 每次启动用独立 profile `aram_overlay_<ts>`，并清理 1 天前的旧目录。
  5. 全屏游戏（RiotWindowClass 2560×1440）抢占 Z 序压住 topmost 浮窗 → 新增 `attach_to_game()`（GWLP_HWNDPARENT 附属）+ `keep_on_top()` 高频置顶 + app.py `topmost_loop` 每 0.3s 执行，必要时把游戏窗口从 TOPMOST 降级。
  6. 紧凑模式（?overlay=1）在 400 物理像素宽下右侧列被裁 → 改为内联布局：梯队徽章+胜率跟在英雄名后，「选它·重算出装」按钮移到卡片底部。
- 浮窗最终形式：右上 (2144,15)-(2544,835)、400×820、透明度 0.92、紧凑三块（英雄/海克斯/出装）、隐藏自检与设置、位置可切左/中/右、OCR 区域收窄到 [0.18,0.14,0.58,0.60] 避开浮窗、默认不遮中央卡牌与小地图/技能栏。
- 新增 `show_overlay.py` / `show_overlay.bat`：用户双击即可启动服务并同步弹出浮窗，会打印窗口矩形做自检（避免我会话里启动的后台进程被回收）。
- 实测：OCR 在对局里成功识别到「黎明使者的坚决 / 术士果汁盒 / 暴击律动 / 巨人杀手」；客户英雄乌迪尔；state 返回 overlayBounds [2144,15,2544,835]；窗口化状态下截图确认浮窗可见。
- 剩余限制：全屏独占/全屏优化时游戏可能仍压住浮窗；若高频置顶仍无效，需让用户把游戏改「窗口化」或对 League of Legends.exe 禁用全屏优化。

## 追加：真正的根因（64 位句柄）+ 桌面启动器
- 用户仍反馈看不到。诊断发现服务/守护端口全空（我会话启动的后台进程每次都被沙箱回收），且浮窗 Z 序一直在游戏之后。
- **关键根因**：`HWND_TOPMOST = -1` 以 Python int 传给 `SetWindowPos`，ctypes 默认按 32 位 c_int 转换 → 0x00000000FFFFFFFF，在 64 位 Windows 上不是合法的 `(HWND)-1`，`SetWindowPos` 静默失败。所有置顶/摆位调用从未生效。
- 修复：`HWND_TOPMOST/NOTOPMOST` 改为 `ctypes.c_void_p(-1)/(-2)`，模块级显式声明 `SetWindowPos/GetWindowLongW/SetWindowLongW` 的 argtypes/restype。
- 验证：修复后 Z 序前 3 = 浮窗 > League of Legends (TM) Client > WorkBuddy；真机截图确认浮窗盖在游戏画面右上，显示出门装/鞋子/第 1-3 件等，中央战斗区与右下小地图未被遮挡。`show_overlay.py` 同样能达成 Z 序正确，并打印浮窗矩形 (2144,16)-(2544,836)。
- 交付：`%USERPROFILE%\Desktop\ARAM-Assistant-Launch.bat`（桌面一键启动器，cd 到项目目录后调用 show_overlay.py）。用户必须自己双击一次，服务才会常驻；我会话内的进程无法保留。
- 曾尝试 `schtasks` 注册计划任务立即拉起，被安全策略黑名单拒绝；明确不得绕过，已放弃该路径。
- 结论口径：以后用户说"看不到"，先查 8765/8766 端口（多半是服务没跑 → 让用户双击桌面启动器），再查窗口 Z 序。
